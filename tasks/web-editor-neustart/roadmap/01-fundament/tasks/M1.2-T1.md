# M1.2-T1 – Entwurfs- und URL-Arbeitszustand

## Intention

Baum und Node-Editor erhalten einen gemeinsamen, testbaren Web-Schreibweg:
erster Write startet genau einen Entwurf, weitere Writes verwenden ihn.

## Voraussetzungen und Referenzen

- M1.1-T1 abgeschlossen; [Konzept](../../../Konzept.md), Ist-Doku
  `docs/Transaktionen-und-Historie.md`, `docs/Zielgruppen-und-Content.md`.
- Ausgangspunkt: `Web/State/WorkspaceState.cs`,
  `Web/State/WebReadContextResolver*`, `Web/WebServiceRegistration.cs` und
  bestehende Application-Services für Snapshot/Transaction.

## Scope und Nicht-Ziele

- **Verbindlich:** Eine schlanke Koordination unter `Web/Workflow/` kapselt
  Begin/Resume/Write für Web-Aktionen. Sie setzt Actor aus
  `ICurrentUserService`/`DummyCurrentUserService`, `Client = "Web UI"` und
  `Purpose = "Wissenspflege"` ohne Formular, serialisiert konkurrierende
  erste Writes pro Arbeitsbereich,
  vergleicht vor Begin den geladenen Current Snapshot mit dem aktuellen und
  gibt `TransactionId` nach erfolgreichem Begin auch bei gescheiterter
  anschließender Mutation an die UI zurück. Existing-Transaction-Writes
  starten nie eine zweite Transaction.
- **Verbindlich:** `audienceId` und `transactionId` in der Node-URL sowie
  `/drafts/{TransactionId}` sind maßgeblich; `WorkspaceState` darf diese
  Information nur flüchtig spiegeln. Letzte Zielgruppe wird nur bei fehlendem
  URL-Wert eingesetzt; ein fremder Entwurf nie still gewählt. Fehler-/Dirty-
  Zustände bleiben für die UI unterscheidbar.
- **Nicht:** Editor-/Baumansichten, neues Datenmodell, Auth, Merge/Rebase oder
  zweite fachliche Transaction-Implementierung.
